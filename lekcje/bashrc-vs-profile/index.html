.bashrc vs .profile vs .bash_profile: why your alias works in one terminal and not the other

Why does an alias work in a new terminal tab but not over SSH? See exactly which startup file bash reads for login and interactive shells, reproduce the classic trap where creating ~/.bash_profile silently stops ~/.profile and ~/.bashrc from loading, fix it with one line, and learn where aliases and environment variables belong.

# Login shell vs interactive shell
$ su demo -c "bash -l -c true"
-> reading ~/.profile
-> reading ~/.bashrc
$ grep -A2 'BASH_VERSION' /home/demo/.profile
if [ -n "$BASH_VERSION" ]; then
    # include .bashrc if it exists
    if [ -f "$HOME/.bashrc" ]; then
$ su demo -c "bash -i -c true" 2>/dev/null
-> reading ~/.bashrc
$ su demo -c "bash -l -i -c 'type deploy'" 2>/dev/null
-> reading ~/.profile
-> reading ~/.bashrc
deploy is aliased to `echo deploying the app'

# The trap: creating .bash_profile
$ echo 'export PATH="$HOME/bin:$PATH"' > /home/demo/.bash_profile
$ su demo -c "bash -l -i -c 'type deploy || echo deploy is missing'" 2>/dev/null
deploy is missing
$ su demo -c "bash -i -c 'type deploy'" 2>/dev/null
-> reading ~/.bashrc
deploy is aliased to `echo deploying the app'

# The fix: one line
$ echo '[ -f ~/.profile ] && . ~/.profile' >> /home/demo/.bash_profile && cat /home/demo/.bash_profile
export PATH="$HOME/bin:$PATH"
[ -f ~/.profile ] && . ~/.profile
$ su demo -c "bash -l -i -c 'type deploy'" 2>/dev/null
-> reading ~/.profile
-> reading ~/.bashrc
deploy is aliased to `echo deploying the app'

/work/home is the home folder of a developer. Their aliases (ll,
gs) work in every new terminal tab, but over SSH they are gone.
You can try both kinds of shell with that home folder:
  new terminal tab:  HOME=/work/home bash -i -c 'alias'
  SSH login shell:   HOME=/work/home bash -l -i -c 'alias'

1. Add the alias  logs='tail -n 20 app.log'  so that every new
   terminal tab (interactive, non-login shell) has it.
2. Make login shells get all the aliases too. Keep .bash_profile
   and what it sets (PATH with ~/bin, EDITOR); don't copy the
   aliases into more than one file.
