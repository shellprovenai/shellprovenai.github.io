tar and gzip without the usual mistakes: back up a folder, skip the junk, verify the archive

Back up a folder with tar and gzip the right way: create and list an archive, see why an absolute path ends up nested three folders deep when you extract it (and fix it with -C), skip node_modules and log files with --exclude, prove the archive matches the disk with tar --compare, and restore a single file.

# The project folder
$ find project -type f | sort

# Create an archive and look inside
$ tar -czf backup.tgz project
$ ls -lh backup.tgz

project/src/

project/node_modules/
project/node_modules/lib/
project/node_modules/lib/bundle.bin

# The trap: absolute paths
$ tar -czf abs.tgz /lab/work/project
tar: Removing leading `/' from member names
$ tar -tzf abs.tgz | head -3
lab/work/project/
lab/work/project/src/
lab/work/project/src/app.py
$ mkdir /tmp/restore && tar -xzf abs.tgz -C /tmp/restore && find /tmp/restore -maxdepth 3 -type d
/tmp/restore
/tmp/restore/lab
/tmp/restore/lab/work
/tmp/restore/lab/work/project
$ tar -czf good.tgz -C /lab/work project && tar -tzf good.tgz | head -3
project/
project/src/
project/src/app.py

# Skip the junk with --exclude
$ tar -czf small.tgz --exclude=node_modules --exclude='*.log' -C /lab/work project
$ tar -tzf small.tgz
project/
project/src/
project/src/app.py
project/src/config.ini
project/logs/
project/README.md
$ ls -lh good.tgz small.tgz
-rw-r--r-- 1 root root 8.1M Nov 21 20:16 good.tgz
-rw-r--r-- 1 root root  282 Nov 21 20:16 small.tgz

# Verify the backup
$ gzip -t small.tgz && echo "gzip OK"
gzip OK
$ tar -dzf small.tgz -C /lab/work && echo "archive matches the disk"
archive matches the disk
$ echo "debug = true" > project/src/config.ini && tar -dzf small.tgz -C /lab/work
project/src/config.ini: Mod time differs
project/src/config.ini: Size differs
$ printf 'debug = false\n' > project/src/config.ini && tar -czf small.tgz --exclude=node_modules --exclude='*.log' -C /lab/work project

# Restore one file
$ mkdir /tmp/one && tar -xzf small.tgz -C /tmp/one project/src/config.ini && find /tmp/one -type f
/tmp/one/project/src/config.ini

Do it yourself, without the video. Download the practice folder and run sh start.sh — it opens a throwaway container (podman or docker), nothing touches your system.

PRACTICE — lesson 11: tar and gzip without the usual mistakes
-------------------------------------------------------------
/work/sites/blog is a small blog. cache/ is 3 MB of generated
pages, and the *.tmp files are editor leftovers.
/work/old-backup.tgz is an older backup of the blog.

1. Create /work/blog.tgz (tar + gzip) with the blog, but without
   the cache folder and without any *.tmp file. Paths inside the
   archive must start with blog/ (not work/sites/blog/).
2. posts/hello.md was broken by a bad edit. Restore ONLY that file
   from /work/old-backup.tgz. Everything else in the blog must
   stay as it is: about.md is newer than the backup, keep it.
   List the old archive first: how are its paths stored?

Check: sh /practice/check.sh     Answer: /practice/solution.md

Inside, sh check.sh tells you when you are done. Stuck? solution.md — but try first.
