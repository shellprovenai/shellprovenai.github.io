Cron job not running? It works in the terminal, here's why it fails in cron

A script runs fine when you type it, but does nothing from cron. Using a real cron daemon, this video logs the job's output to see the actual error, dumps cron's environment to show its tiny PATH and different working directory, fixes both in the crontab, and explains the percent-sign trap that silently breaks date commands in cron.

Commands

Exactly as run in the video. Full folder with setup script and log: terminal-tutorials/cron-not-running.

# A script that works
$ cat backup.sh
#!/bin/sh
report-tool > report.txt
echo "saved report"
$ ./backup.sh && cat report.txt
saved report
report for demo: 42 orders

# Schedule it, and log the output
$ cat first.cron
# min hour day month weekday  command
* * * * * /lab/jobs/backup.sh >> /tmp/backup.log 2>&1
* * * * * env > /tmp/cron-env.txt
$ crontab first.cron && crontab -l
# min hour day month weekday  command
* * * * * /lab/jobs/backup.sh >> /tmp/backup.log 2>&1
* * * * * env > /tmp/cron-env.txt

# Why it fails
$ cat /tmp/backup.log
/lab/jobs/backup.sh: 2: report-tool: not found
saved report
$ cat /tmp/cron-env.txt
HOME=/root
LOGNAME=root
PATH=/usr/bin:/bin
SHELL=/bin/sh
PWD=/root
$ ls /root
report.txt

# The fix: PATH and cd in the crontab
$ cat fixed.cron
PATH=/usr/local/bin:/usr/bin:/bin
# min hour day month weekday  command
* * * * * cd /lab/jobs && ./backup.sh >> /tmp/backup.log 2>&1
* * * * * echo "ran at $(date +%H:%M)" >> /tmp/broken.log
* * * * * echo "ran at $(date +\%H:\%M)" >> /tmp/fixed.log
$ crontab fixed.cron

# Check it
$ tail -n 1 /tmp/backup.log && cat report.txt
saved report
report for demo: 42 orders

# The percent-sign trap
$ cat /tmp/broken.log
cat: /tmp/broken.log: No such file or directory
$ cat /tmp/fixed.log
ran at 20:08

Do it yourself, without the video. Download the practice folder and run sh start.sh — it opens a throwaway container (podman or docker), nothing touches your system.

PRACTICE — lesson 09: a cron job that really works
--------------------------------------------------
/work/jobs/dump.sh makes a nightly database dump. It calls the
tool dumptool from /work/bin and writes dump.sql into the folder
it runs in. By hand it works:
  cd /work/jobs && PATH=/work/bin:$PATH ./dump.sh
Don't change dump.sh or dumptool. Write a crontab file
/work/dump.cron and install it with crontab:

1. Run dump.sh every day at 02:30 so that it works in cron's
   environment (PATH is only /usr/bin:/bin, the job starts in
   /root), dump.sql lands in /work/jobs, and BOTH the output and
   the errors are appended to /work/logs/dump.log.
2. Then change the log to one file per day, named with today's
   date, like /work/logs/dump-2026-11-25.log ($(date +%F)).
   Install the new version too.

Check: sh /practice/check.sh     Answer: /practice/solution.md
(check.sh runs your job the way cron would: same PATH, same
folder, same handling of special characters.)

Inside, sh check.sh tells you when you are done. Stuck? solution.md — but try first.
