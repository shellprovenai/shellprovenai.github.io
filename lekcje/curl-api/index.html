curl for APIs: headers, JSON bodies, timings, cookies, and the status code trap in scripts

Use curl against an HTTP API without surprises, on a small test server running locally in the container: read the status code and headers, see why curl exits with 0 on a 404 (and fix it with -f or -w), send an auth header, post a JSON body with the right Content-Type (or --json), measure timings with -w, keep a login session with a cookie jar, and check the status code in a script.

# Status codes and the exit code trap
$ curl -s http://localhost:8000/health
{"status": "ok"}
$ curl -si http://localhost:8000/health
HTTP/1.0 200 OK
Server: BaseHTTP/0.6 Python/3.13.5
Date: Sat, 21 Nov 2026 22:53:04 GMT
Content-Type: application/json
Content-Length: 17

{"status": "ok"}
$ curl -s http://localhost:8000/nope; echo "curl exit code: $?"
{"error": "not found"}
curl exit code: 0
$ curl -sf http://localhost:8000/nope; echo "curl exit code: $?"
curl exit code: 22

# Send a header
$ curl -s -w ' -> %{http_code}\n' http://localhost:8000/api/items
{"error": "missing or wrong token"}
 -> 401
$ curl -s -H "Authorization: Bearer demo-token" http://localhost:8000/api/items
[{"id": 1, "name": "keyboard"}, {"id": 2, "name": "monitor"}]

# POST a JSON body
$ curl -s -w ' -> %{http_code}\n' -d '{"name":"cable"}' http://localhost:8000/api/items
{"error": "expected Content-Type: application/json"}
 -> 415
$ curl -s -w ' -> %{http_code}\n' -H 'Content-Type: application/json' -d '{"name":"cable"}' http://localhost:8000/api/items
{"id": 3, "name": "cable"}
 -> 201
$ curl -s -w ' -> %{http_code}\n' --json '{"name":"mouse"}' http://localhost:8000/api/items
{"id": 4, "name": "mouse"}
 -> 201

# Timings with -w
$ curl -s -o /dev/null -w 'status %{http_code}, connect %{time_connect}s, total %{time_total}s\n' http://localhost:8000/slow
status 200, connect 0.000184s, total 0.401015s

# Keep a session with cookies
$ curl -s -c cookies.txt -X POST http://localhost:8000/login
{"logged_in": true}
$ curl -s http://localhost:8000/me; curl -s -b cookies.txt http://localhost:8000/me
{"error": "not logged in"}
{"user": "demo"}

# Check the status code in a script
$ code=$(curl -s -o /tmp/body.json -w '%{http_code}' http://localhost:8000/nope); if [ "$code" != 200 ]; then echo "request failed with $code"; fi
request failed with 404

PRACTICE — lesson 20: curl for APIs
-----------------------------------
A small helpdesk API runs in this container on http://localhost:8080
(test server, nothing leaves the container). The API key is in
/work/api-key.txt; the API wants it in the header X-API-Key.

1. Create a ticket with the title "disk full on web1": POST the JSON
   {"title":"disk full on web1"} to http://localhost:8080/tickets.
   Read the key from the file, don't type it into the command.
   You should get status 201. Plain -d is not enough here!
   (GET /tickets with the same header lists the tickets.)
2. /work/backup-check.sh says "backup OK", but there is no backup of
   db1 at all: the server answers 404. Fix the script so that on an
   error answer it does NOT print "backup OK" and exits with a non-zero
   code. For a real backup (try BACKUP_URL=http://localhost:8080/backups/web1
   sh /work/backup-check.sh) it must still print "backup OK".

Check: sh /practice/check.sh     Answer: /practice/solution.md
Start over: sh /practice/setup.sh

Inside, sh check.sh tells you when you are done. Stuck? solution.md — but try first.
